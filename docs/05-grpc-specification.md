# Foundation v3 — gRPC & Protobuf Specification

## Overview

gRPC is the sole communication channel between the stratum server and the core server. It replaces the v2 architecture of local PostgreSQL → remote PostgreSQL data transfer.

---

## Why gRPC

| Requirement | gRPC | REST/HTTP | Raw TCP |
|---|---|---|---|
| Typed contract | Protobuf (compile-time) | OpenAPI (runtime) | Manual |
| Streaming | Bidirectional | SSE/WebSocket bolt-on | Manual |
| Binary efficiency | Protobuf (compact) | JSON (verbose) | Manual |
| TLS | Built-in | Built-in | Manual |
| Flow control | HTTP/2 built-in | None | Manual |
| Code generation | Rust + TypeScript | OpenAPI codegen | N/A |
| Batching | Native (repeated fields) | Manual | Manual |

## Service Definition

```protobuf
// proto/stratum_ingest.proto

syntax = "proto3";

package foundation.stratum.v1;

option java_package = "com.foundation.stratum.v1";

// StratumIngest is the service exposed by foundation-core
// and called by foundation-stratum to submit mining data.
service StratumIngest {
  // Submit a batch of validated shares.
  // Called periodically by the stratum forwarder.
  // Shares are archived, score_buckets updated, hashrate accumulated.
  rpc SubmitShares (ShareBatch) returns (ShareAck);

  // Report a block found by a miner.
  // Called immediately when a share solves a block.
  rpc SubmitBlock (BlockFound) returns (BlockAck);

  // Report network state changes (difficulty, height, hashrate).
  // Called when the stratum server detects new blocks on the network.
  rpc ReportNetwork (NetworkState) returns (NetworkAck);

  // Health check — core confirms it is ready to receive data.
  rpc Ping (PingRequest) returns (PingResponse);
}
```

## Message Definitions

### Share Messages

```protobuf
// A batch of shares to submit
message ShareBatch {
  // Identifier of the stratum server instance
  string stratum_id = 1;
  
  // The shares in this batch
  repeated Share shares = 2;
}

// A single validated share
message Share {
  // Unique identifier (UUID v4), generated by stratum server
  string uuid = 1;
  
  // Unix timestamp in milliseconds when share was received
  int64 timestamp = 2;
  
  // Unix timestamp in milliseconds when share was submitted to WAL
  int64 submitted = 3;
  
  // Miner's wallet address
  string miner = 4;
  
  // Worker name (from address.worker authorization)
  string worker = 5;
  
  // Stratum server identifier (e.g., "europe-01")
  string identifier = 6;
  
  // SHA-256 hash of miner's IP address (privacy)
  string ip_hash = 7;
  
  // Connection port number
  int32 port = 8;
  
  // Difficulty of the submitted share
  double share_diff = 9;
  
  // Current block difficulty at time of share
  double block_diff = 10;
  
  // Difficulty assigned to the miner (VarDiff target)
  double client_diff = 11;
  
  // Blockchain height at time of share
  int32 height = 12;
  
  // Block reward (only relevant if block_valid = true)
  double reward = 13;
  
  // Block hash (only if block_valid = true)
  string hash = 14;
  
  // Coinbase transaction hash (only if block_valid = true)
  string transaction = 15;
  
  // Whether the share passed difficulty validation
  bool valid = 16;
  
  // Whether the share was stale (job not found)
  bool stale = 17;
  
  // Whether the share solved a block
  bool block_valid = 18;
  
  // Error message if share was invalid (empty if valid)
  string error = 19;
  
  // Coin type: "primary" or "auxiliary"
  string coin_type = 20;
  
  // Whether this share was on a solo mining port
  bool solo = 21;
  
  // Coin identifier (e.g., "raptoreum", "blocx") — multi-coin routing
  string coin = 22;
}

// Acknowledgment from core server
message ShareAck {
  // UUIDs that were successfully received and archived
  repeated string accepted_uuids = 1;
  
  // Number of shares that were duplicates (already in archive)
  int32 duplicate_count = 2;
  
  // Number of shares that failed to process
  int32 failed_count = 3;
  
  // Error messages for failed shares (uuid → error)
  map<string, string> errors = 4;
}
```

  double difficulty = 8;
  
  // Block reward
  double reward = 9;
  
  // Coinbase transaction hash
  string transaction = 10;
  
  // "primary" or "auxiliary"
  string coin_type = 11;
  
  // Whether on a solo mining port
  bool solo = 12;
  
  // Port where the block-solving share was submitted
  int32 port = 13;
  
  // Coin identifier (e.g., "raptoreum", "blocx")
  string coin = 14;

message BlockAck {

## Communication Patterns

### Normal Operation

```
Stratum                                Core
  │                                      │
  ├── SubmitShares(batch of 500) ───────>│
  │                                      ├── Archive shares
  │                                      ├── UPSERT score_buckets
  │<──────────────── ShareAck(500 uuids) ┤
  │                                      │
  │  [repeat every 1s]                   │
  │                                      │
  ├── ReportNetwork(state) ─────────────>│
  │<──────────────── NetworkAck ─────────┤
```

### Block Found (Immediate)

```
Stratum                                Core
  │                                      │
  │  [miner submits block-solving share] │
  │                                      │
  ├── SubmitBlock(block) ───────────────>│
  │                                      ├── Create pending block
  │                                      ├── Detect competing blocks
  │<──────────────── BlockAck(block_id) ─┤
  │                                      │
  │  [next share batch includes the      │
  │   block-solving share as well]       │
  │                                      │
  ├── SubmitShares(batch with block) ───>│
  │                                      ├── Archive (includes block share)
  │<──────────────── ShareAck ───────────┤
```

### Network Failure & Recovery

```
Stratum                                Core
  │                                      │
  ├── SubmitShares(batch) ──────X        │  [network down]
  │                                      │
  │  [forwarder: gRPC error]             │
  │  [shares stay in WAL as 'pending']   │
  │  [backoff: 1s → 2s → 4s → ... 60s]  │
  │                                      │
  │  [miners keep submitting]            │
  │  [shares keep accumulating in WAL]   │
  │                                      │
  │  ... hours later, network restored   │
  │                                      │
  ├── Ping ─────────────────────────────>│
  │<──────────────── PingResponse ───────┤
  │                                      │
  │  [drain accumulated shares]          │
  ├── SubmitShares(batch 1 of N) ───────>│
  │<──────────────── ShareAck ───────────┤
  ├── SubmitShares(batch 2 of N) ───────>│
  │<──────────────── ShareAck ───────────┤
  │  ... continues until WAL drained     │
```

## Authentication

### Server TLS + Bearer Token — Recommended

The core server presents its TLS certificate (internal CA). Stratum servers authenticate via a shared bearer token in gRPC metadata on every request.

```
// gRPC metadata
authorization: Bearer <shared-secret>
```

```toml
# Stratum config
[forwarder]
core_address = "https://core.pool.example:50051"
tls_ca = "certificates/core-ca.crt"              # CA that signed core's cert
auth_token = "your-shared-secret-here"            # Bearer token

# Core config
[grpc]
tls = true
cert = "certificates/core-server.crt"
key = "certificates/core-server.key"
auth_token = "your-shared-secret-here"            # Must match stratum config
```

**Pros:** Simple, no certificate management per stratum instance, easy rotation
**Cons:** Token rotation requires coordinated config change on all stratum instances

> **Note:** mTLS (mutual TLS with client certificates) is an alternative if stronger per-instance identity is needed in the future. The gRPC interceptor interface supports swapping auth strategies without protocol changes.

## Error Handling

### gRPC Status Codes Used

| Code | Meaning | Stratum Behavior |
|---|---|---|
| OK (0) | Success | Process ACK, mark shares forwarded |
| INVALID_ARGUMENT (3) | Malformed request | Log error, fix data, skip batch |
| UNAUTHENTICATED (16) | Bad credentials | Log critical, halt forwarder |
| PERMISSION_DENIED (7) | Revoked access | Log critical, halt forwarder |
| UNAVAILABLE (14) | Core server down | Retry with exponential backoff |
| RESOURCE_EXHAUSTED (8) | Core overloaded | Reduce batch size, retry |
| DEADLINE_EXCEEDED (4) | Request timeout | Retry same batch |
| INTERNAL (13) | Core server error | Retry with backoff |

### Retry Policy

```
On UNAVAILABLE / DEADLINE_EXCEEDED / INTERNAL:
    attempt: 1 → wait 1s
    attempt: 2 → wait 2s
    attempt: 3 → wait 4s
    attempt: 4 → wait 8s
    ...
    max wait: 60s
    max attempts: unlimited (shares must not be lost)
    
    Shares remain in WAL until successfully acknowledged.
```

### Idempotency

All operations are idempotent via UUID deduplication:
- `SubmitShares`: shares with duplicate UUIDs → `ON CONFLICT DO NOTHING` in archive, counted in `duplicate_count`
- `SubmitBlock`: blocks with duplicate UUIDs → treated as already-received
- Safe to retry any failed request without risk of double-counting

## Performance Targets

| Metric | Target |
|---|---|
| ShareBatch size | 100–1000 shares per call |
| SubmitShares latency (p99) | < 100ms |
| SubmitShares throughput | 50,000+ shares/sec |
| SubmitBlock latency (p99) | < 50ms |
| gRPC connection count | 1 per stratum instance (multiplexed) |
| Max message size | 4 MB (configurable) |

### Batching Strategy

The stratum forwarder should batch shares for efficiency:
- **Time-based**: send every `interval_ms` (default: 1000ms)
- **Size-based**: send when batch reaches `batch_size` (default: 500)
- **Whichever comes first**: prevents both latency spikes and tiny batches
- Under light load: shares sent within 1s of reception
- Under heavy load: shares sent in optimal-size batches

## Code Generation

### Rust (tonic + prost)

```toml
# foundation-stratum/Cargo.toml
[build-dependencies]
tonic-build = "0.12"
```

```rust
// foundation-stratum/build.rs
fn main() -> Result<(), Box<dyn std::error::Error>> {
    tonic_build::configure()
        .build_server(false)  // stratum is client-only
        .build_client(true)
        .out_dir("src/generated")
        .compile(&["../proto/stratum_ingest.proto"], &["../proto"])?;
    Ok(())
}
```

### TypeScript (ts-proto)

```json
// foundation-core/package.json scripts
{
  "proto:generate": "protoc --plugin=./node_modules/.bin/protoc-gen-ts_proto --ts_proto_out=./src/generated --ts_proto_opt=outputServices=grpc-js --ts_proto_opt=esModuleInterop=true ../proto/stratum_ingest.proto"
}
```

ts-proto generates idiomatic TypeScript:
```typescript
// Generated types (example)
export interface Share {
  uuid: string;
  timestamp: number;
  miner: string;
  worker: string;
  // ...
}

export interface ShareBatch {
  stratumId: string;
  shares: Share[];
}
```
